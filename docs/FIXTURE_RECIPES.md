# Fixture Recipes — Real-Producer Corpus

Step-by-step instructions for creating the real-producer `.xlsx` fixtures by hand.

**Why by hand:** the value of this corpus is that the files come from *outside* this project. Every real spreadsheet application writes OOXML differently, and the parser must survive that variance. A file generated by our own tooling can only confirm what we already assumed — so these files must be produced by real applications.

**Time needed:** ~25 minutes. No installation required.

---

## Rules (read once)

1. **Keep every file tiny** — a handful of cells is enough. Large files add nothing.
2. **One producer per file.** After downloading a file, never open and re-save it in a different application — that rewrites the XML and destroys the producer identity that makes the fixture valuable.
3. **macOS warning:** double-clicking an `.xlsx` opens Numbers, which may offer to save/convert. Don't. If you must inspect a file, close it without saving.
4. **Exact filenames matter** — tests will reference them.
5. **Don't record expected values here.** Golden values get read out of the finished files programmatically, never typed from memory.
6. If an application can't do something in a recipe, skip that part and note it — never fake it in another app.

---

## Producer A — Microsoft Excel for the web

Free with any Microsoft account: <https://www.office.com> → Excel → Blank workbook.
Download each finished file with **File → Save As → Download a copy** (`.xlsx`).

Target folder: `core/parser/src/test/resources/fixtures/excel/`

### A1 · `values-basic.xlsx`

Cell types: text, number, boolean.

| | A | B | C |
|---|---|---|---|
| **1** | Product | Price | InStock |
| **2** | Olma | 12.5 | TRUE |
| **3** | Anor | 300 | FALSE |
| **4** | Uzum | 0.75 | TRUE |

Type `TRUE`/`FALSE` in uppercase so Excel stores real booleans, not text.

### A2 · `strings.xlsx` — the most important file in the corpus

Excel stores repeated text in a shared string table. This is the only real test of that code path.

Column A, rows 1–6, one value per row:

```
apple
banana
apple
cherry
banana
apple
```

Nothing else in the sheet. No formatting.

### A3 · `styles-basic.xlsx`

Column A, rows 1–6 — each row gets exactly one style applied:

| Row | Text | Formatting to apply |
|---|---|---|
| 1 | Bold | **bold** |
| 2 | Italic | *italic* |
| 3 | Red | red font color |
| 4 | Yellow | yellow fill (cell background) |
| 5 | Center | center horizontal alignment |
| 6 | Right | right horizontal alignment |

### A4 · `merged-frozen.xlsx`

1. Type `Hisobot` in **A1**, then select **A1:C1** → Merge & Center.
2. Row 2 headers: A2 `Nomi`, B2 `Soni`, C2 `Narxi`.
3. Rows 3–5, any short values (e.g. `Olma / 10 / 5000`).
4. Select cell **B3**, then **View → Freeze Panes → Freeze Panes** (this freezes row 1–2 and column A simultaneously).

### A5 · `dates.xlsx`

Column A, rows 1–4. Type these exactly; Excel should right-align them, which confirms they were recognized as dates/times rather than text:

```
2024-01-15
13:30
2024-01-15 13:30
2024-12-31
```

If any cell stays left-aligned it was stored as text — reformat that cell as Date or Time.

### A6 · `uzbek-text.xlsx`

Non-ASCII content and a non-ASCII sheet name.

1. Rename the sheet tab to: `Jadval 1`
2. Column A, rows 1–5:

```
O'zbekiston
Toshkent
Farg'ona
Namangan
Andijon
```

The apostrophes are the point — they exercise UTF-8 handling end to end.

## Producer B — Google Sheets

Any Google account: <https://sheets.google.com> → Blank.
Download with **File → Download → Microsoft Excel (.xlsx)**.
Name the document itself with the target filename so the download lands correctly.

Target folder: `core/parser/src/test/resources/fixtures/gsheets/`

Create three files, reusing the recipes above verbatim:

- `values-basic.xlsx` — same content as A1
- `merged-frozen.xlsx` — same as A4 (freeze via **View → Freeze → Up to row 2**, then **View → Freeze → Up to column A**)
- `uzbek-text.xlsx` — same as A6

Same content, different producer, is exactly the point: any divergence between these files and Excel's is variance the parser must absorb.

---

## Producer C — WPS Office *(optional, third priority)*

Only if WPS is already installed or available on a phone. Target folder: `fixtures/wps/`

- `values-basic.xlsx` — same as A1
- `strings.xlsx` — same as A2 (WPS is known to sometimes emit inline strings instead of a shared table — valuable divergence if it happens)

## Producer D — Apple Numbers *(optional bonus, macOS only)*

Numbers is a genuinely distinct OOXML writer and is already on the Mac. If included, create the folder `fixtures/numbers/` and export via **File → Export To → Excel…**

- `values-basic.xlsx` — same as A1
- `uzbek-text.xlsx` — same as A6

---

## Not required: `password.xlsx`

Web-based Excel cannot set a file password, and the encrypted-container path (OLE/CFB detection) is already covered by byte-level unit tests. Treat this fixture as optional; it can be added later if a desktop Excel becomes available.
