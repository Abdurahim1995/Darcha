# Fixture corpus — `:core:parser`

Golden test inputs for the XLSX parser. Every parser feature is proven by a
fixture with **known expected values** (CLAUDE.md "Testing", TECH_SPEC §12).

## Producers

Fixtures are grouped by the tool that produced them, because each emits subtly
different OOXML (TECH_SPEC §7 "Producer variance"):

| Folder | Producer | Status |
|---|---|---|
| `synthetic/` | Generated by `tools/gen_fixtures.py` (openpyxl) + one hand-crafted file | ✅ committed (T1) |
| `excel/` | Microsoft Excel Online | ✅ committed, golden-locked (T9) |
| `gsheets/` | Google Sheets export | ⬜ optional future addition |
| `libreoffice/` | LibreOffice Calc | ⬜ optional future addition |
| `wps/` | WPS Office | ⬜ optional future addition |

Recipes for producing real-producer files by hand live in
[docs/FIXTURE_RECIPES.md](../../../../../../docs/FIXTURE_RECIPES.md). After adding
files, verify them with:

```bash
python3 tools/check_fixtures.py            # all producer folders
python3 tools/check_fixtures.py excel      # one folder
```

The checker is read-only — it never rewrites a fixture, because re-saving a file
through another application destroys the producer identity that makes it useful.

## Discovery: openpyxl never writes shared strings

**openpyxl 3.1.5 always writes string cells as `inlineStr` and never emits
`xl/sharedStrings.xml`** (see `openpyxl/cell/_writer.py`, lines 21–22 and 70–79).

Two consequences, both useful for T4 (shared-string parsing):

1. **`values-basic.xlsx` has no `sharedStrings.xml` at all** → it doubles as the
   *"missing shared string table"* case (a valid workbook whose strings are all
   inline). T4 must handle this without error.
2. **`strings-shared.xlsx` is hand-crafted** minimal OOXML (not real producer
   output) so that a genuine shared string table exists to test → the *"present
   shared string table"* case, with de-duplication and index resolution.

Together these two fixtures fully cover T4's read paths (present, missing, and
`inlineStr`). The hand-crafted file is structurally validated by round-tripping
through openpyxl; **OWNER will additionally open it in LibreOffice / Google
Sheets to confirm real-app compatibility.**

## Detailed golden values

### `strings-shared.xlsx`

Shared string table (`xl/sharedStrings.xml`, in order):

| Index | Value |
|---|---|
| 0 | `fruit` |
| 1 | `apple` |
| 2 | `banana` |
| 3 | `cherry` |

Cell → index → resolved value (column A):

| Cell | Index | Value |
|---|---|---|
| `A1` | 0 | fruit |
| `A2` | 1 | apple |
| `A3` | 2 | banana |
| `A4` | 1 | apple |
| `A5` | 3 | cherry |
| `A6` | 2 | banana |
| `A7` | 1 | apple |

`A2`, `A4`, `A7` all resolve to `apple` via the same index `1`.

### `sparse-gaps.xlsx`

0-based `(row, col)` coordinates the parser must produce (and nothing else):

| Cell | (row, col) | Value |
|---|---|---|
| `A1` | (0, 0) | "start" (text) |
| `C5` | (4, 2) | 42 (number) |
| `AA100` | (99, 26) | "end" (text) |

Column `AA` = index 26; row 100 = index 99.

### `dates.xlsx`

| Cell | Value | numFmtId | Kind | Excel serial |
|---|---|---|---|---|
| `A1` | 2024-01-15 | 14 (builtin) | date | 45306 |
| `A2` | 13:30:00 | 21 (builtin) | time | 0.5625 |
| `A3` | 2024-01-15 13:30:00 | 22 (builtin) | datetime | 45306.5625 |
| `A4` | 2024-12-31 | 164 (custom `yyyy-mm-dd`) | date | 45657 |

Note: openpyxl also *defines* an unused custom numFmt `165` (`yyyy-mm-dd
h:mm:ss`) that no cell references — a harmless real-world artifact. Serials use
the 1900 epoch (`date1904=false`).

## Real-producer corpus — `excel/`

Eight files written by **Microsoft Excel Online**, golden-locked in
`ExcelFixturesTest.kt`. Every expected value there was read out of the committed
files, never typed from memory.

| File | Covers | Golden highlights |
|---|---|---|
| `values-basic.xlsx` | text, numbers, real booleans | `B2`=12.5, `B3`=300, `B4`=0.75; `C2`/`C4`=TRUE, `C3`=FALSE (`t="b"`); sheet `Sheet` |
| `strings.xlsx` | shared string de-duplication | table `[apple, banana, cherry]`; `A1..A6` → indices `0,1,0,2,1,0` |
| `styles-basic.xlsx` | fonts, fill, alignment | `A1` bold; `A2` italic; `A3` font `FFFB0007`; `A4` fill `FFFFFF0B`; `A5` center/center; `A6` right/center |
| `merged.xlsx` | merged range | one merge `A1:C1`; anchor `A1`="Hisobot", covered cells empty; 10 cells |
| `frozen.xlsx` | frozen pane, column only | `xSplit=1`, **no `ySplit`** → `FrozenPanes(1, 0)`; 12 cells |
| `frozen-both.xlsx` | frozen pane, both axes | `xSplit=1`, `ySplit=2`, `topLeftCell=B3` → `FrozenPanes(1, 2)`; 12 cells |
| `dates.xlsx` | builtin date formats | serials `45306`, `0.5625`, `45306.5625`, `45657`; numFmt `14 / 20 / 22 / 14`; no shared strings |
| `uzbek-text.xlsx` | UTF-8 + non-ASCII sheet name | sheet `Jadval 1`; `A1..A5` = O'zbekiston / Toshkent / Farg'ona / Namangan / Andijon |

### Producer variance this corpus captures

Divergences between Excel Online and the synthetic (openpyxl) corpus — each one
is behaviour the parser must absorb, and none of it is guessable from a file our
own tooling wrote:

| Aspect | synthetic (openpyxl) | Excel Online |
|---|---|---|
| Text storage | always `inlineStr`, no `sharedStrings.xml` | always a shared string table |
| Time format for 13:30 | builtin `21` (`h:mm:ss`) | builtin `20` (`h:mm`) |
| Default sheet name | `Sheet1` | `Лист1` (the UI was Russian) |
| Colors | exactly what was requested (`FFFF0000`) | its own palette (`FFFB0007`) |
| Alignment | horizontal only | horizontal **and** an explicit vertical |

### Quirks deliberately locked, not cleaned

- **`frozen.xlsx` has no `ySplit`.** Excel emitted `<pane xSplit="1" state="frozen"
  topLeftCell="B1"/>`, freezing only the first column even though the recipe aimed
  at row + column. The test asserts `FrozenPanes(1, 0)`: a missing `ySplit` must
  parse as zero rather than crash. `frozen-both.xlsx` is its companion, with both
  attributes present (`xSplit=1 ySplit=2`), so the two together cover the
  attribute-present and attribute-absent paths from the same producer.
- **`uzbek-text.xlsx` carries junk cells.** A paste left `A1:E10` populated, most
  cells holding a lone newline string (shared index 1), for 50 cells total. Real
  files contain exactly this kind of debris, so it is asserted rather than tidied
  away.

## Performance fixture

`big-50k-rows.xlsx` — a producer-agnostic scale fixture for the M2 performance
target (~50,000 data rows × 7 columns; mostly numeric, with one repeated text
column and a boolean). It has **no golden values** — it exercises scroll/render
throughput, not producer variance — so it is generated separately and is not
part of the default 8-fixture run.

## Regenerating

```bash
pip install openpyxl        # tested with 3.1.5
python3 tools/gen_fixtures.py          # the 8 small golden fixtures
python3 tools/gen_fixtures.py big       # big-50k-rows.xlsx (large, perf only)
```

Output is (near-)deterministic: document timestamps and hand-crafted ZIP entry
times are pinned, so regeneration does not churn git. Exact ZIP bytes may still
vary across openpyxl versions, but the parsed golden values above will not.
